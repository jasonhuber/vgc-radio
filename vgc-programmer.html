Radio link

First connection — do these in order
  1. Quit the VGC phone app, and turn Bluetooth off on the phone. The radio serves one controller at a time and phones silently reconnect.
  2. Put the radio into Bluetooth pairing mode from its own menu.
  3. Press Connect radio and pick VR-N76.
  4. Accept the system pairing dialog. This is required — the radio drops any link that is not bonded, which looks exactly like a failed connection. The browser delegates bonding to the OS, so an OS pairing prompt is the browser pairing. Only needed once.

If the picker comes up empty, use Show all Bluetooth devices — BLE advertising names differ from the name the OS shows.

APRS / BSS settings

What do APRS, BSS, KISS and TNC mean?

APRS (Automatic Packet Reporting System) is the open ham-radio standard for broadcasting your position and short text over the air — any APRS software, and sites like aprs.fi, can decode it. Using it requires a licensed callsign (N7WGP qualifies).

BSS is Vero Telecom's own packet protocol — same idea, no callsign check, but only other Benshi-family radios and the VGC app understand it. It's the fallback for anyone without a ham license.

The radio only ever transmits one of the two — set Format below to whichever fits.

TNC (Terminal Node Controller) is the packet modem — historically a separate box between a radio and a computer, translating between radio audio and digital bytes. This radio has one built in.

KISS is a dead-simple framing protocol so a computer can talk to a TNC without knowing anything radio-specific — it just gets raw packet bytes in and out. This app talks to the radio's TNC the same way, over the same Bluetooth link already used for everything else on this page (not a separate Bluetooth connection). Sending packets isn't built yet — see PLAN.md item 2; receiving already shows up in the Protocol log below as packet in….

Callsign / SSID — your callsign identifies the station; the SSID (0–15) is a suffix (like the -9 in N7WGP-9) used when one callsign runs several devices at once, so they don't collide on the map.

Symbol — the two-character code that picks the icon APRS software draws for you (a car, a house, an HT, …). Leave it as whatever the radio ships with if unsure.

Share location — turns GPS beaconing on/off and how often (in seconds) a position report goes out.

PTT-release options — what gets sent automatically the instant you let go of the transmit button: your position, your ID text, and/or your BSS ID.

Not covered by this panel yet: the digipeater Path (e.g. WIDE1-1, via SET_APRS_PATH/GET_APRS_PATH — decoded, just not wired into this UI yet) and which RF channel carries packet data (part of general radio settings, a separate not-yet-built page — see PLAN.md). Set those from the radio's own screen or the VGC phone app for now: Menu → General Settings → APRS Settings → Path, and Menu → General Settings → Digital Mode → Digital Channel.

Read first — write sends back every field, including ones not shown here.

Not yet round-tripped against real hardware — Read from radio first, check the values look sane, then Write to radio. If a write fails, the protocol log below will show the radio's actual error status.

Repeater map

Click a site to filter the channel list to it. Ring labels are miles from the QTH. Site positions are approximate — named peaks and city/landmark centroids, not surveyed antenna locations.

Radio layout — what goes where

Click a slot to target it, then press + on a channel below to place it there. A channel may appear in as many groups and slots as you like. Slot numbers are the radio's memory positions.

Group names live on the radio itself (READ_REGION_NAME / WRITE_REGION_NAME) — this reads and writes them for real, not just in the browser. Byte layout isn't from benlink; it's a community decode confirmed against real hardware (Ylianst/HTCommander, Apache-2.0), not yet round-tripped by this app specifically — Read group names first to confirm it decodes sane text before trusting a write.
